# 阳澄股份大闸蟹全链路溯源品控管理系统 (PRD V1.4)

> **面向阳澄股份内部供应链管理及大型商超渠道（山姆会员店等）合规审核的大闸蟹全链路溯源与品控数字化平台。**

---

## 📖 1. 系统核心本质与定位

本系统**不是防伪防串货系统**，而是一套**数量闭环管控与供应链合规证明系统**：

- **不追踪单只蟹**：蟹扣为养殖户码（一户一码），不含批次号、无唯一序列号、不扫码。
- **核心业务价值**：通过对 **“额度核定、活蟹入池、蟹扣领用、出库发运”** 四个关键数量节点的强事务级校验与**逐日轧平对账**，用不可篡改的数字化台账严密证明：
  $$\text{公司向市场/渠道发出的带扣阳澄湖大闸蟹总量} \le \text{签约养殖户的理论核定总产量}$$
- **商超审核支撑**：为山姆会员店（Sam's Club）等大型零售渠道的供应商审核提供批次级反向追溯拓扑链条与四大合规台账。

## ⚖️ 2. 五大数量守恒定律（系统硬约束）

```
[养殖户核定额度] (面积 × 600 只/亩)
       │
       ▼ (入池总量 ≤ 年度总额度；超额需 ADMIN 特批留痕)
[原料批次入池] (入库即入池，一批一公母一规格，暂养池按规格复用)
       │
       ▼ (领用量 ≤ min(在池存活合计, 养殖户剩余额度))
[蟹扣领用申请] (动态计算双重可领余量)
       │
       ▼ (单票出库数 ≤ 批次在池存活 & 单票出库数 = 渠道订单数)
[出库打包发运] (打包时绑扣，扣随货走，支持物流单号回填)
       │
       ▼ (逐日轧平: 当日领扣 = 绑扣出库 + 当日退回 + 当日作废)
[日清日结闭环]
```

### 核心数学不等式链：
$$\text{累计出库数} \le \text{累计已核销蟹扣数} \le \text{累计领扣数} \le \text{累计入池数} \le \text{年度核定总额度}$$

## 🛠️ 3. 技术栈选型

- **全栈框架**：Next.js 15 (App Router + React 19 + TypeScript 5.x)
- **数据库与 ORM**：PostgreSQL / SQLite + Prisma ORM 6.x（行级锁与 ACID 强事务保障）
- **UI 组件库**：严格遵循 **shadcn/ui** 规范（基于 Radix UI 底层与 Sonner 消息通知）
- **样式体系**：Tailwind CSS v4（基于语义化 CSS 变量与设计令牌）
- **图标体系**：lucide-react（严格使用 `data-icon`）
- **动画体系**：motion (Framer Motion 13.x)
- **表单与校验**：React Hook Form + Zod（前后端共享强类型校验）
- **数据导出**：原生 Web Blob + UTF-8 BOM 规范（零体积依赖，100% 兼容 Excel/WPS）
- **容器与 CI/CD**：Docker + Docker Compose + GitHub Actions

## 🚀 4. 快速开始与本地运行

### 4.1 本地安装与开发

```bash
# 1. 克隆代码并安装依赖
git clone https://github.com/your-org/yangcheng-tracehub.git
cd yangcheng-tracehub
pnpm install

# 2. 生成 Prisma 客户端并同步数据库结构
pnpm prisma:generate
pnpm prisma:push

# 3. 注入真实业务仿真种子数据 (养殖户、暂养池、山姆门店、初始批次与角色等)
pnpm prisma:seed

# 4. 启动开发服务器
pnpm dev
```
打开浏览器访问 [http://localhost:3000](http://localhost:3000)。

### 4.2 常用开发脚本

| 脚本命令 | 说明 |
| :--- | :--- |
| `pnpm dev` | 启动 Next.js 本地开发服务器 |
| `pnpm typecheck` | 执行 TypeScript 静态类型检查 (`tsc --noEmit`) |
| `pnpm lint` | 执行 ESLint 代码规范检查 |
| `pnpm prisma:generate` | 重新生成 Prisma Client 类型定义 |
| `pnpm prisma:push` | 将 Prisma Schema 变更同步到数据库 |
| `pnpm prisma:seed` | 重新执行种子数据注入 |

### 4.3 Docker 容器化一键拉起

```bash
docker compose up -d
```

## 📊 6. 核心功能与页面导航

| 路由地址 | 模块名称 | 核心业务功能与品控卡控 |
| :--- | :--- | :--- |
| `/` | **总览看板** | 四大数量流转统计、数量闭环等式证明、待审事项预警与额度消耗全景图 |
| `/farmers` | **养殖户主档** | 养殖户与围网水域维护，面积实时核定 600 只/亩额度，入池与领扣统计 |
| `/batches` | **原料批次** | 到厂入池登记（校验规格与额度）+ 药残监测报告上传查阅 + 盘点损耗历史（$>5\%$ 强制风控告警） |
| `/pools` | **暂养池监控** | 8 大暂养池在养公母与规格档位软锁定、按规格同池复用、防混池拦截与防删保护 |
| `/tags` | **蟹扣核销** | 蟹扣申领（动态算 $\min(\text{在池存活}, \text{剩余额度})$）+ 当日逐日轧平核销表单与日结历史 |
| `/outbound` | **出库管理** | 出库发运申请（单票核对 + 在池存活校验）+ 物流单号后回填留痕 |
| `/approvals` | **品控审批中心** | 统一审批蟹扣领用与出库发货（审批通过自动扣减批次在池存活，支持驳回） |
| `/ledgers` | **四大合规台账** | 养殖户台账、领扣台账、出入库台账、出库订单台账，**支持一键导出带 BOM 的 CSV/Excel** |
| `/trace` | **全链路追溯** | 输入出库单号一键反向穿透完整追溯链条，自动出具《山姆渠道数量闭环合规证明单》 |
| `/stores` | **渠道与门店** | 渠道分类（如山姆会员店）、门店档案管理、历史出库关联与防误删校验 |
| `/users` | **用户与权限** | 5 大预置 RBAC 角色配置、用户账号管理与状态启停 |
| `/login` | **统一认证** | 快速身份认证与角色切换登录入口 |

## 👥 7. 用户角色与权限隔离 (RBAC)

系统顶部导航栏提供 5 大预置角色的即时视角切换与强权限隔离：

| 角色标识 | 角色名称 | 核心权限与职责边界 |
| :--- | :--- | :--- |
| `ADMIN` | **系统超级管理员** | 拥有全局最高权限；支持超额入池特批操作（特批记录强制审计留痕）；全量数据可读可写。 |
| `FARMER_ADMIN` | **养殖户专员** | 负责签约养殖户主档、围网水域与面积档案维护，核定年度额度。 |
| `WAREHOUSE_ADMIN` | **仓库主管** | 原料批次入池登记、盘点损耗实盘录入、蟹扣领用申请、出库申请与物流单号回填。 |
| `QA_DIRECTOR` | **品控总监** | 蟹扣领用审批、出库发运审核、损耗超标（$>5\%$）调查与批次品质管控。 |
| `CHANNEL_VIEWER` | **山姆品控代表** | 专属渠道审计只读视角，仅可见发往山姆门店的批次与追溯单，自动阻断跨渠道数据。 |
